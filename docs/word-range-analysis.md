# Signed machine-word ranges

`kernel/finite_exact/word_range.mojo` decides, exactly, whether integer
arithmetic stays inside a signed `w`-bit two's-complement word
`W_w = [-2^(w-1), 2^(w-1) - 1]`, for `1 <= w <= 32`.

## Why

An arithmetic that computes modulo `2^w` and cannot report an overflow — a
homomorphic integer such as TFHE `FheInt32`, whose carry is as encrypted as
its value — returns a wrong number, not an error, when an intermediate leaves
`W_w`. The only place that overflow can be decided is before evaluation, from
public information: a range for every input.

## What the module provides

| Name | Meaning |
|---|---|
| `word_min(w)`, `word_max(w)` | the bounds of `W_w` |
| `wrap_word(x, w)` | the representative of `x mod 2^w` in `W_w`, exact for every 64-bit `x` |
| `WordRange(w, lo, hi)` | `[lo, hi] ⊆ W_w`, rejected unless `lo <= hi` and both lie in `W_w` |
| `add`, `sub`, `mul`, `neg`, `hull` | the natural interval extension (Moore 1966) over `Z`, rejected unless the result lies in `W_w` |
| `clamp(bounds)` | the image of `x ↦ max(lo, min(x, hi))`: exactly `[clamp(a), clamp(b)]` by monotonicity, and inside `bounds` whatever the operand |

For accepted ranges `A`, `B` and an operation `∘`,

```text
x ∈ A, y ∈ B  ⟹  x ∘ y ∈ A ∘ B ⊆ W_w,
```

and `A ∘ B` is the least such interval (the hull of the image). A rejected
range is sticky: every operation on it is rejected. Mixing widths is rejected.
Nothing raises (the `finite_exact` convention apart from `checked_int`).
Since `|bound| <= 2^31`, every bound product fits a 64-bit `Int`, so a
rejection means exactly "leaves the word".

Clamping is what makes a declared range enforceable on data nobody vouches
for: a `w`-bit ciphertext holds some value of `W_w`, and `W_w.clamp([lo, hi])`
is `[lo, hi]`, so a homomorphic `min`/`max` (which cannot overflow) establishes
the range instead of assuming it.

## What the module does not claim

That wrapped evaluation equals exact evaluation is the consumer's theorem:
`wrap_word` is the identity on `W_w` and a ring homomorphism `Z → Z/2^w`, so
if every node of an expression has an accepted range, induction on the
expression gives `wrapped = exact`. `larsbx/tclmesh` states and proves it in
Lean (`spec/TclMesh/Range.lean`) for its private circuits; this repository
supplies the arithmetic and the corpus, not the proof. The enclosure is the
natural extension, so it over-approximates under the dependency problem
(`x - x` on `[0, 1]` is `[-1, 1]`): a rejected circuit may still be safe, and
a rejection is never a counterexample.

## Conformance

`conformance/word_range_v1.txt` is generated by the independent Python
reference `reference/word_range_reference.py` (unbounded integers, wrap by
offset rather than by conditional subtraction, and on words of at most four
bits every range checked against the enumerated image of its operands):

```sh
pixi run word-range-vectors   # the committed corpus equals the reference's
pixi run test-word-range      # the Mojo kernel replays every row exactly
```

Rows are tab-separated: `make W LO HI RESULT`, `wrap W X RESULT`, and
`range OP W A B RESULT`, where a range is `LO,HI` or `refused`, `B` is `-` for
`neg`, and for `clamp` `B` is the bounds. Both tasks are part of
`pixi run test`. Consumers replay the file byte-for-byte and pin it by SHA-256.
